# Рефакторинг интерфейса и эффектов

`TestNewLevelSelect` слита в `main` обычным merge-коммитом `756b484`, без конфликтов. В `main` также сохранён фикс камеры `1bfe8b5`. Ветка `Refactoring` создана от этого состояния. Уровни, их физика, прочность ящиков, превью, звуки, сохранения прогресса и переход к следующему уровню перенесены вместе с твоими изменениями.

## Где редактировать интерфейс

Кнопки, подписи, карточки, звёзды, ползунки и итоговые окна уже сохранены в сценах. Скрипты управляют их состоянием, текстом и анимациями. Фабрик интерфейса и его удаления во время игры больше нет. На кнопках назначены постоянные обработчики **Button → On Click**; их можно увидеть и изменить в Inspector.

| Сцена / объект в Hierarchy | Что находится внутри |
| --- | --- |
| `MainMenu / MainButtons / MainButtonsPanel` | Играть, настройки, выход |
| `MainMenu / MainButtons / SettingsButtonPanel` | Громкость музыки и эффектов, назад |
| `MainMenu / MainButtons / LevelSelectPanel / Root` | Карточки уровней, превью, звёзды, подсветка, замки, стрелки, точки страниц, сообщение «СКОРО» |
| Каждый уровень / `GameplayCameraCanvas` | Катапульта, вся карта, цель, подсказка управления |
| Каждый уровень / `GameplayPauseCanvas` | Кнопка паузы, страницы паузы и настроек |
| Каждый уровень / `LevelScoreCanvas` | Очки |
| Каждый уровень / `LevelCompleteCanvas` | Победа, звёзды, очки, число выстрелов, далее |
| Каждый уровень / `LevelDefeatCanvas` | Поражение, начать заново, главное меню |
| Каждая сцена / `SceneTransition / LoadingCanvas` | Заставка и индикатор загрузки из общего prefab |

Скрытая панель остаётся в Hierarchy. Для оформления включи её GameObject и, если необходимо, поставь **CanvasGroup → Alpha = 1**. При запуске менеджеры восстановят стартовую видимость. Шрифты, картинки, размеры, расположение и цвета кнопок редактируются на самих объектах; игра больше не применяет `MenuButtonStyle` автоматически.

Если хочешь разово применить прежний общий стиль, открой контекстное меню компонента **MenuControlFeedback → Применить MenuButtonStyle к этой кнопке**. Действие поддерживает Undo. Палитра и шрифт остаются в `Assets/Resources/MenuButtonStyle.asset`.

Экран загрузки редактируется в `Assets/Prefabs/SceneTransition.prefab`, чтобы оформление сразу изменилось во всех семи сценах. Логотип, название, слоган, тексты и длительности берутся из `Assets/Resources/SceneTransitionSettings.asset`. После смены логотипа или палитры можно применить настройки через контекстное меню компонента **SceneTransition → Применить оформление из SceneTransitionSettings** в prefab: оно также переставит название под логотип. Ручное оформление prefab не затирается при запуске; автоматически обновляется только содержимое.

## Настройки игры и камеры

- Боезапас: `GameManager → LevelSession → Max Projectiles`. По уровням стоит **2 / 3 / 4 / 5 / 5**; значение включает кота в катапульте и очередь. Настройка пяти префабов и двух поз описана в `CATS_AND_QUEUE.md`.
- Если все обязательные цели очищены, уровень сразу засчитывается как полная победа. Если коты закончились раньше, через 5 игровых секунд после последнего выстрела оцениваются мыши; при необходимости игра ещё ждёт остановки снарядов и построек, чтобы учесть цепные столкновения. Все обязательные мыши — 3 звезды; иначе число звёзд считается как `ROUND(убитые / всего обязательных мышей × 3)`, но неполный результат ограничен 1–2 звёздами (любое убийство даёт минимум 1). Если не убита ни одна мышь — поражение. Кнопка перезапуска восстанавливает время и боезапас.
- «ДАЛЬШЕ»: `LevelCompleteCanvas / Overlay / ContinueButton → LevelSession.GoToNextLevel`. Последовательно открывает `Gameplay → Level2 → Level3 → Level4 → Level5`; после последнего доступного уровня открывает главное меню.
- Камера: `Main Camera → GameplayCameraController → Impact Transition Duration = 0.75`. Переход к попаданию использует плавную кривую и сохраняет масштаб полёта. `Impact Size` теперь задаёт приближение при ручном выборе «ЦЕЛЬ».
- Звёзды карточек зависят от числа убитых обязательных мышей; итоговый экран показывает счёт мышей и число выстрелов. Старые пороги выстрелов в `LevelProgress.Levels` остаются резервом только для карт без обязательных мышей. Прочность и сопротивление ящиков по-прежнему настраиваются в `LevelTarget`.

## Частицы и трассер

`Assets/Prefabs/Projectile.prefab` содержит готовый `ComicTracer` с тремя TrailRenderer: контур, цветная лента и светлая сердцевина. `ProjectileComicEffects` включает их при выстреле и гасит после контакта. Длина, ширина, время жизни, цвета и параметры попадания по-прежнему настраиваются на этом компоненте.

В каждом уровне заранее размещён `Assets/Prefabs/ComicImpactPool.prefab`: **12 эффектов**, по **3 ParticleSystem** в каждом — пыль, щепки и вспышка. `ComicEffectsPool` выбирает свободный эффект. При переполнении повторно используется самый старый слот. Попадание не создаёт GameObject, ParticleSystem, Texture2D или Material.

Формы и материалы сохранены в `Assets/Materials/ComicFX`; они повторяют прежние процедурные формы. Пул полностью прогревается невидимыми частицами при старте сцены, пока переход закрывает игру. Изменение физики прочного ящика для этого не потребовалось.

На `GameManager` также заранее размещён prefab `TrajectoryDots` с **256** точками прогноза; ссылки назначены в списке `SlingshotController → Dots`. При необходимости увеличить ёмкость добавь точки в prefab и в этот список. Количество видимых точек зависит от прогноза столкновения. Все коты создаются из готовых префабов при старте попытки; следующий кот переходит из очереди в катапульту тем же объектом.

## Что сокращено

- Из `LevelSession`, `PauseMenuController`, `GameplayCameraController`, `LevelSelectController`, `SceneTransition` удалены построение Canvas, кнопок, подписей, страниц и их очистка.
- Карточки выделены в небольшой `LevelCardView`; сохранены свайпы, колесо, стрелки клавиатуры, страницы и защита от случайного клика после свайпа.
- Звуковые источники и компоненты отклика кнопок заранее добавлены в сцены. Менеджер звука сохраняет музыку, настройки и звук выстрела при переходах.
- Удалены неиспользуемые `TrajectoryDotTrail`, `MenuSpriteFactory`, `StarSpriteFactory`, `MenuColorBlock`, лишние ссылки и устаревшие копии установочного пакета в `Tools/particles_and_ammo/Files`.
- Исправлены пути резервной загрузки джинглов победы после переноса звуков в `Resources/Audio/Effects`.
- Комментарии и заголовки настроек игровых скриптов переведены на русский.
- Игровые C#-скрипты уменьшились примерно с **5757 до 3637 строк** (на 37%). Размер YAML сцен увеличился, поскольку интерфейс теперь сохранён в них.

Старый `Tools/level_tools/gen_levels.py` остановлен защитной проверкой: он переносил только игровые объекты и потерял бы новый UI. Новые уровни создавай дублированием `Gameplay` в Unity; настрой объекты и `Forced Level Id`, добавь сцену в Build Settings и запись в `LevelProgress.Levels`.

## Проверки и замеры

Предыдущие проверки выполнялись в отдельной копии проекта на Unity **6000.6.5f1** с отдельным профилем сохранений. После добавления оценки по убитым мышам и пятисекундной задержки Unity-прогон ещё не выполнялся; формульные проверки и сценарий `Tools/validation/ValidationRunner.cs` обновлены. Рабочий редактор и игровой прогресс пользователя не используются для тестов.

Проверки предыдущей версии прошли:

- Компиляция текущих игровых скриптов и Editor-проверки.
- Все семь сцен: обязательные ссылки, отсутствие потерянных скриптов, постоянные обработчики кнопок, спрайты, материалы, системы частиц и порядок подсветки карточек.
- `Boot → MainMenu`, настройки громкости, страницы выбора, повторное открытие меню без замены объектов кнопок.
- Пауза → настройки → продолжить; пять настоящих запусков снаряда, блокировка шестого, поражение после остановки и перезапуск.
- Приоритет победы на последнем выстреле, сохранение прогресса, «ДАЛЬШЕ → Level2», загрузка уровней 3–5, выход после последнего уровня.
- Физические попадания снарядов в прочный ящик Level2: прочность уменьшается, частицы появляются, ящик сбивается после нужного числа ударов.
- 106 запусков эффекта используют прежние 12 слотов / 36 систем частиц без создания новых объектов.
- Проверены рендеры интерфейса в 1920×1080: меню, карточки, настройки, пауза, поражение и победа.

Замер вызова эффекта через `Stopwatch`: прежний первый запуск — **454.256 мс**, повторные — **1.495–1.914 мс**. После сохранения объектов и полного прогрева: первый запуск в последних прогонах — **0.282–0.330 мс**, повторные — **0.024–0.082 мс**. Это замеры CPU-вызова в редакторе; они подтверждают устранение дорогого первого создания эффекта, но не измеряют полное время GPU-кадра или FPS готовой сборки.

В изолированном редакторе также возникала ошибка его поискового индекса `UnityEditor.Search.SearchDatabase`. Она записана отдельно от игровых ошибок; игровые сценарии завершились без ошибок.

Повторить проверку ссылок: в Unity **BPG → Проверить интерфейс всех сцен**. Проверка сохраняет и восстанавливает набор открытых сцен; изменённые сцены предлагается сначала сохранить.

Повторить игровые проверки из PowerShell:

```powershell
./Tools/validation/run_play_checks.ps1
```

Если Unity установлена в другом месте, передай `-UnityPath 'полный путь к Unity.exe'`. Скрипт создаёт отдельный проект в системной временной папке `BPGChecks/PlayChecks-*`, использует локальный кэш пакетов, запускает скрытый редактор и сохраняет `play-checks.txt`, `unity.log`, предупреждения редактора и PNG-рендеры. Рабочая Unity не сможет удалить эту копию при очистке своего `Temp`. Первый импорт может занять несколько минут. `-MinimalEditor` исключает Unity AI Assistant и Inference только из тестовой копии, использует Direct3D 11 и отключает Burst для тестового запуска. Тесты ускоряют задержки выстрелов и управляют состоянием целей при проверке итоговых окон; попадания по прочному ящику проверяются физически.
